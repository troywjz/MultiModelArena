# 架构说明

## 系统边界

MultiModelArena 负责三件事：

1. 读取用户配置的多个模型。
2. 编排一组结构化评估任务、扰动脚本和程序化评分流程。
3. 保存过程证据并生成 Markdown 结果报告。

系统不负责托管模型、不保存用户 API Key、不提供在线账号体系。

## 核心模块

### 配置层

负责从环境变量读取模型配置、任务配置和运行参数。MVP 使用 `.env` 风格配置，仓库只提交 `.env.example`。

建议环境变量形态：

```text
ARENA_MODELS=deepseek-chat,qwen-max,gpt-4.1-mini
ARENA_MODEL_DEEPSEEK_CHAT_PROVIDER=openai_compatible
ARENA_MODEL_DEEPSEEK_CHAT_BASE_URL=https://api.example.com/v1
ARENA_MODEL_DEEPSEEK_CHAT_API_KEY=...
ARENA_MODEL_DEEPSEEK_CHAT_MODEL_NAME=deepseek-chat
```

### Provider 适配层

统一不同供应商的请求、响应、错误和用量信息。当前支持 fake provider、OpenAI-compatible Chat Completions 接口和 Anthropic-compatible Messages 接口，后续再按需要增加原生供应商适配器。

### 评测编排层

负责生成任务、调用模型、组织多阶段扰动、解析结构化 JSON、执行程序化评分。评测流程应显式保存每一步输入、输出、评分和错误。

当前主流程：

1. 所有模型独立完成个人行动领域基准任务。
2. 调度器按 `base_url` 分组；不同请求入口并发执行，同一请求入口内部串行排队。
3. 系统注入价值变化、新证据等扰动。
4. 模型按固定 JSON 协议更新建议。
5. 规则评分器根据任务结构、隐藏偏好、候选方案和扰动预期打分。
6. 在不增加模型调用的前提下，对已返回响应做拆解诊断，识别约束锚定、权衡方法、风险可逆性、行动具体性和方法多样性。
7. 如果启用 `ARENA_EMBEDDING_ENABLED=true`，把模型回答字段和本地参考答案字段向量化，计算余弦相似度语义分。
8. 统计领域分、Decision Quality 评分框架结果、响应拆解分、参考答案语义分、行为指纹和角色适配。

旧版互评流程仍保留在 `arena run`，当前模型能力评估主流程使用 `arena assessment-run`。

### 存储层

保存两类数据：

- JSONL 原始事件：请求摘要、响应、评分、错误、时间和 token 用量。
- SQLite 汇总数据：运行、模型、任务、维度得分、角色建议和报告索引。
- SQLite 向量缓存：启用 embedding 时，默认在 `.arena-cache/embedding-cache.sqlite3` 缓存参考答案和回答片段向量，避免清空临时运行目录时丢失缓存并重复消耗调用成本。

### 报告层

生成本地 Markdown 结果报告。报告文件默认写入根目录 `report-output/`，命名格式为 `model-arena-YYYYMMDD-HHMMSS-参与模型名称.md`。完整原始数据仍保存在 `runs/` 下的 `events.jsonl` 和 `summary.json`。

报告至少包含：

- 总览排名。
- 每个模型的领域分、Decision Quality 评分框架结果、响应拆解评估、行为计数和适合角色。
- 每个模型的方法与分析角度指纹，以及“为什么这说明模型有某种能力”的证据说明。
- 程序化规则分和失败项。
- 证据摘录、任务定义和原始记录文件链接，不在 Markdown 中内嵌完整回答。
- 运行配置摘要，但不展示 API Key。
- 启用 embedding 时展示参考答案语义相似度和语义角色适配说明。

### 程序化评分层

总评分只来自可复现规则，不使用模型裁判。第一版规则包括：

- JSON 字段完整性。
- 备选方案数量。
- 明显坏方案规避。
- 专业边界提示。
- 扰动响应。
- 7 天 / 30 天行动计划和复盘条件。
- 响应拆解诊断：约束锚定、价值拆解、权衡推理、信息追问、风险与可逆性、行动可执行性、变化适配、校准边界和方法多样性。
- 可选参考答案语义相似度：按问题框架、价值识别、备选方案、推荐排序、风险复盘、行动计划和专业边界拆解后做 embedding 余弦相似度比较。

当前 `assessment-run` 不调用模型裁判，也没有单独配置 judge model。总评分来自本地规则、响应拆解、角色适配和可选参考答案语义相似度。

## 评分维度

初始维度建议：

- 准确性：事实、推理和约束遵循。
- 完整性：覆盖需求和边界情况。
- 协作性：能否吸收反馈、改进答案、形成共识。
- 稳定性：输出格式、错误率和多轮一致性。
- 工程可用性：可执行性、结构化程度和落地成本。
- 表达质量：清晰度、简洁度和面向用户的说明能力。

## 团队角色画像

报告中的角色建议应从证据推导，不直接按模型品牌预设。初始角色集合：

- 通用主持专家：框定议题并维持讨论顺序。
- 用户价值专家：识别真实目标、偏好和价值冲突。
- 信息审查专家：区分事实、假设和未知信息。
- 方案生成专家：提出多样化备选方案。
- 权衡仲裁专家：比较收益、成本、机会成本和约束匹配度。
- 风险专家：识别不确定性、止损条件、可逆性和预案。
- 执行规划专家：把结论转成 7 天、30 天和复盘节点行动。
- 红队专家：挑战推荐方案，寻找反例、失败模式和过度自信。
- 结论整合专家：整合多角色意见，形成最终建议、分歧点和触发条件。

## 安全约束

- API Key 只能从环境变量或本地未提交文件读取。
- 日志和报告必须脱敏密钥、鉴权头和完整请求 URL 中的敏感参数。
- 对外部模型调用设置超时、重试上限和失败记录。
- 原始用户任务可能包含敏感信息，默认只写入本地，不上传第三方存储。
