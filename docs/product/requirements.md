# 产品需求

## 用户

目标用户是需要选择、组合或评估多个 AI 大模型的开发者、产品经理、AI 应用团队负责人和技术顾问。

## 核心问题

用户面对多个模型时，通常缺少统一、可复现、可解释的比较依据。本项目要帮助用户回答：

- 每个模型分别擅长什么、不擅长什么？
- 在关键维度上分数如何？
- 哪些模型适合在团队协作中承担什么角色？
- 这些结论基于哪些任务和证据？

## MVP 验收标准

- 用户可以通过环境变量配置至少 2 个 OpenAI-compatible 模型。
- 程序可以运行一组内置评测任务，并记录多轮交互过程。
- 每个模型得到结构化结果：优点、缺点、维度分数、适合角色、证据摘录。
- 程序生成一个本地 HTML 报告，浏览器打开即可查看。
- 报告和日志不泄露 API Key。
- 即使某个模型调用失败，整体运行仍能完成并在报告中展示失败原因。

## 非目标

- MVP 不做在线账号体系。
- MVP 不做付费、权限和团队协作后台。
- MVP 不保证评测结论是绝对客观排名，必须展示任务范围和局限。
- MVP 不直接存储或同步到云端。

## 初始评测任务类型

- 需求分析任务：从模糊需求中提炼目标、约束和验收标准。
- 工程设计任务：给出模块设计、数据流和风险。
- 代码审查任务：发现潜在 bug、测试缺口和安全问题。
- 综合决策任务：在多个方案中权衡成本、风险和交付速度。

## 报告信息架构

1. 运行摘要：时间、模型数量、任务数量、失败数量。
2. 总体结论：推荐模型组合和团队角色分配。
3. 模型卡片：优缺点、分数、推荐角色、主要证据。
4. 维度对比：表格和图表。
5. 任务详情：每轮回答、互评摘要、最终评分理由。
6. 局限性：任务覆盖范围、失败调用、评分不确定性。
